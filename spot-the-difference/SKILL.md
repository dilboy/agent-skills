# 生成找不同关卡

交付能直接试玩或导入游戏的成对图片和可验证答案。保留用户指定的命名、顺序、发布目录及差异点数量。批量任务按原图顺序处理。若用户指定 `_a` 为原图，排除 `_b`、备份和过去的导出目录。先确认任务是生成、补做、审查还是只导出，复用范围内的已验收结果。

## 生成

1. 让使用者只提供原图及必要的难度、数量和策略。打开实际画面。自动批量时可由已获准的视觉模型返回候选物件、范围和替换建议。单张试做或视觉服务不可用时，直接查看图片或带坐标的缩略图选点。记清实际用的是哪条路径。
2. 模型负责重画少数有意义的物件或构件。优先改轮廓、构件形状或材质，保留物件的位置、连接关系、透视、光照和画风。局部换色、原地形变和背景修补可以补齐其他差异。避开人物面部、手、文字和已有改动。详细方法见 [让替换自然](references/semantic-editing.md)。
3. 给图像编辑模型发送含少量上下文的裁图、范围提示和具体替换要求。将返回图对齐，并只在获准区域内合成，边沿适度羽化。在替换区域之外沿用原图。合成过程中保留同尺寸无损版本和每处实际使用的改动范围。
4. 若要求递进难度，按原顺序预设难度梯度。用大小、色差、邻域纹理及用户要求的点数调整。根据合成图实测，重选或微调不达标的项。保留各级点数和难度的区别，分数是图像估算，试玩效果由人工抽查。

## 批量与校验

- 先做代表样张，确认替换协调、差异可辨并且成本可接受，再批量。采用用户指定的模型、预算和并行上限。需要外部调用时核实可用配置，保存逐图状态以便补跑。遇到额度、权限或凭据错误时暂停该服务的提交。只在任务范围允许时换策略，并记录真实来源。
- 对齐无损图对后再提取答案。检查尺寸、点数、区域越界、重叠、可见性、选区外变化和命中点。答案框取实际变化范围。遮罩用 0 表示背景，其他灰度值对应差异点编号。另行抽查模型是否确实换了物件，及边缘、原有文字、人物和构图是否自然。
- 优先复用项目自己的生成与验证入口。若已有成对图片和改动范围，需要跨项目导出时，用 [发布与坐标约定](references/export.md) 中的本地脚本。输出按需提供 `_a`/`_b`、逐点信息表、关卡清单、JSON 与遮罩。写回共享目录前对照图片版本、检验暂存成品；授权替换时保留可恢复的旧版。验证发布后的文件数和逐关答案数。
